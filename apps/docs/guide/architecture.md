# Architecture

`packages/contracts` holds Zod schemas for JSON the browser and API share. It does not import Hono, Drizzle, or better-auth.

`apps/api` is a Hono process. `src/features/notes/notes.http.ts` parses requests and status codes. `notes.service.ts` applies owner checks and talks to PostgreSQL. Record routes do the same for synthetic workbench records: the HTTP file parses, and `records.service.ts` applies the owner check, the view and delete permission, and the all-or-nothing delete. Health routes stay next to their SQL check because there is no extra rule to extract. Auth session lookup is shared infrastructure, not a note feature.

`apps/web` is Vite, React, and Tailwind CSS v4. Screens use `Button`, `TextField`, `SelectField`, `Card`, and `Status`. `Button` is the width of its label, with a 44px minimum height. `ActionRow` aligns a wrapping group to the right. Text fields stay full width of their field. The signed-in header offers Dashboard, Records, Collections, Analytics, Activity, and Settings. Guided create, the full form, and export stay on Records. Evidence stays on the record. Notes stay at `/notes` and are not a primary item. The header does not show API liveness. `GET /api/health` and `GET /api/health/ready` remain the probes. Color lives in semantic tokens. The accent is `#06B6D4` in both themes. Light text is `#0F172A` on `#F0FDFA` and white cards. Dark text is `#F8FAFC` on `#0F172A`, with surfaces at `#1E293B`. Primary buttons use the cyan fill and `#0F172A` text, because white on that cyan is about 2.43:1. Cyan text on the light background is about 2.33:1, so light-theme links and secondary buttons keep slate text. Cyan against `#F0FDFA` is about 2.33:1, so the visible control edge and the focus ring are `#0F172A` (about 17:1) and cyan stays an inset highlight. Dark-theme cyan text on `#0F172A` is about 7.35:1, so secondary text there can be cyan. Success is a neutral border and words, not green. The workbench adds `DataTable`, `Drawer`, and `ConfirmDialog` because more than one screen needs them. Feature folders do not import each other. Shared components do not import features. The browser calls `/api` on the same origin. Vite proxies that path in development. The web image and the Helm ingress do the same in deployment.

`pnpm check:architecture` fails the build when those imports are violated, including a cycle inside a package. It is a small script, not a general architecture product.

TypeScript is pinned to 6.0.3 because the ESLint parser in use does not accept TypeScript 7. The web tsconfig sets `ignoreDeprecations` so the `@/` path alias can keep working on TypeScript 6.

The API listens until SIGTERM or SIGINT, then closes the server and the pool. It does not migrate on startup. Readiness fails until the separate migrate command has created the note table.

Export jobs are rows in PostgreSQL. One loop in the API process advances a few locked rows at a time and resumes whatever is still queued or running after a restart. Cancel and retry take the same row lock, so a cancelled attempt cannot later be marked succeeded, and a failed attempt can be retried only once. `JOB_SCHEDULER=false` does not start the loop. Helm refuses more than one API replica while the scheduler is enabled and uses Recreate so two pods do not overlap. A row lock does not turn this into a multi-replica queue. The simulated fail option is stored on that attempt so a failure can be reproduced without calling another service. Retry starts a new attempt that runs to completion. The failed row stays failed.

A comparison reads two published snapshots or two observation windows. It classifies stored ids as added, removed, or changed. For snapshots, the copied fields are title, status, and category only. Optional provenance is environment name, config digest, and code version, shown only when at least one side stored a value. A window is inclusive at the start and exclusive at the end, in UTC. Day and hour labels default to Europe/Paris. A successful window with no observations has a count of zero. A forbidden or invalid request is not shown as zero.

A collection path opens from Collections. The address keeps the collection, snapshot, item, attempt, and status filter. Back removes only the deepest of those ids and leaves the filter in place. Snapshot items are the copied title, status, and category. An attempt is an optional child with a label and a UTC time. A missing label is rejected and nothing is stored. Another account's snapshot id is 404 for the whole response. The item count is not a quality score.

A published snapshot copies the member ids and the title, status, and category at that moment. Category is the latest observation category for that record, or blank when the record has none. The copy is not a foreign key to the live record, so a later rename or delete does not change it. Artifact bytes are not part of the snapshot. Deleting a record still removes its files. The snapshot does not keep a link to those files.

Record sections and files stay on the record the caller owns. Text is rendered as text. A link must be a same-origin path; `javascript:`, `data:`, and external URLs are rejected and nothing is stored. File bytes are a bounded base64 column in PostgreSQL, addressed only by `/api/artifacts/:id/bytes` after an owner check. Responses use `nosniff` and an allowlisted media type. Replacing a file creates a new id. Deleting the record removes its files. This is demo persistence, not object storage, and it is not a malware scanner.

A saved view stores only `q`, `status`, `tag`, `collection`, `sort`, and `page`. Opening it always navigates to `/records` with those fields rebuilt. It is not an open redirect. Curation writes require `canCurate`, which is separate from delete. A missing permission row still means the owner may curate their own records. An explicit `canCurate: false` returns 403 and stores nothing. Bulk membership is one transaction: if any id is missing or owned by someone else, no row in the batch changes.

Analytics reads only stored observations. `observed_at` is UTC. Day buckets use the requested time zone, `Europe/Paris` by default. A count series fills an empty day inside the window with zero. A value series omits that day. The previous window of equal length is the only baseline, and its delta is unknown when that window has no observations. Fixture alpha is labeled demo data.
